# QQ 按钮交互修复与生效记录

日期：2026-11-02。插件版本：v2.0.3；本机 AstrBot：v4.29.4。

## 已确认的问题

1. 插件把所有按钮的 `action_timeout` 都设为 120 秒，包括主菜单和帮助。AstrBot 的[唤醒阶段](https://github.com/AstrBotDevs/AstrBot/blob/v4.29.4/astrbot/core/pipeline/waking_check/stage.py)在插件收到事件前检查该期限；每次点击过期按钮都会发出双语过期提示，插件业务去重无法拦截。
2. 主菜单和帮助在业务消息去重前直接返回，重复投递会再次回复。慢发送期间也没有合并同项连点或过时的导航选择，容易积累响应。
3. 发送路径对所有异常都尝试补发纯文本。超时并不能证明原消息没有送达，补发可能造成重复回复；发送失败后，已经取得的确认结果也缺少原请求恢复流程。
4. 官方 QQ 使用的默认 AstrBot 配置设有每 60 秒 30 次的固定次数限制，策略为 `discard`。超限点击会在插件执行前直接丢弃，这是按钮无响应的独立原因。AstrBot 的[限流实现](https://github.com/AstrBotDevs/AstrBot/blob/v4.29.4/astrbot/core/pipeline/rate_limit_check/stage.py)也支持 `stall` 排队，但本机官方 QQ 没有匹配到使用该策略的另一配置，不能将它认定为本机响应堆积的原因。

## 实际修改

运行代码位于独立插件目录 `D:\AstrBot\data\plugins\astrbot_plugin_mingmiao_stock\`。本交易所仓库只更新说明。

- `main.py`：保留独立按钮监听器；使用点击自己的 `interaction_id` 去重，导航也去重；同用户、同会话的慢导航合并为当前回复和最后一次选择。同项查询、确认与取消合并处理中点击，完成或失效的确认不逐次刷提示。其他用户、其他会话及帮助入口不会等待慢查询。
- 不再设置适配器统一过期时间。帮助与菜单可继续使用，交易和密码重置的两分钟业务期限、身份与原会话校验保持有效。异常回调不能生成开户或新的重置操作。
- 只有明确的 Markdown/键盘拒绝才降级发送。超时不自动补发纯文本，纯文本密码也不做富文本降级重发；保留发送超时。
- `stock_core.py`：取消请求时解除处理中状态；处理中操作不被期限检查误删。临时 HTTP 408/429、服务端错误和异常回执可按原确认码重试。确认结果发送失败时只恢复原幂等请求，向后端重新核对回执，不在内存中缓存旧密码供重发。
- `metadata.yaml` 升级为 v2.0.3；插件 README、原有适配器/业务/HTTP 测试及新增按钮回归测试同步更新。没有增加依赖。

用户另行明确授权关闭固定次数限制后，已在管理界面将默认配置的 `platform_settings.rate_limit.count` 从 `30` 改为 `0` 并保存。对保存前后配置规范化内容的 SHA256 比较确认只有该字段变化；`time=60`、`strategy=discard` 及其他字段不变。AstrBot 保存流程重载对应消息管道，不需要控制 Docker 或重启机器人适配器。

## 兼容、数据与回退

相对于本次改动前仓库版本，Go 后端、交易站/管理站与 AzurPilot 同步端运行代码、接口均未改变。因此“新后端＋旧交易站/管理站/旧 AzurPilot 同步端”和“新前端＋旧后端”两种组合的兼容关系不变；没有据此声称已核实全部线上组件版本。

新版插件沿用既有 bot v2 接口及参数。回执恢复已审查后端 `ResetPassword` 的 `requestId` 幂等、密码版本校验，以及交易确认的 `previewId` 幂等契约；旧后端必须具有这些当前 v2 契约，不能连接 v1。

没有修改业务数据库格式、交易账户、密码、网页会话、实例身份、绑定或行情历史。插件重载会清除内存中的待确认操作及去重状态，原确认码需要重新生成；已经提交的委托不受影响。旧版已发送按钮携带的适配器期限不能由新版插件改写，必须打开新菜单。

旧插件源码、版本、说明及原有限流参数备份保存在插件忽略目录 `.data/button-fix-backup-20261102/`，不含连接凭据或生产数据库。回退插件时恢复旧运行文件并由管理器重载，无需恢复业务数据库；恢复旧版本也会恢复原按钮缺陷。若单独回退限流配置，只按备份的 `rate-limit-change.json` 恢复原参数并保存，不覆盖其他配置。

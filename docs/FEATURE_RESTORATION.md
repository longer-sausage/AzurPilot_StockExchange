# 注册、股票绑定与交易功能恢复

本次以 2026-11-01 开始任务时的三个仓库工作区为比较基线。交易所当时已有未提交的 v2 重构，继续在该实现上增补，保留无关修改；开发阶段未提交、推送或操作生产服务。随后按用户授权完成交易所后端及配套交易站、管理站的生产部署，见 [2026-11-01 部署记录](DEPLOYMENT-2026-11-01.md)。历史差异依据为 [旧功能审计](LEGACY_FEATURE_AUDIT.md)，该文档保留改动前状态。

## 五项目标与实现位置

| 目标 | 结果与主要位置 |
| --- | --- |
| 删除网页注册，机器人命名开户 | `auth.go`、`http.go`、交易站 `Auth.tsx`、插件 `stock_core.py`：群内 `注册 <用户名>` 直接开户，返回随机初始密码；网页注册路由和界面删除，首次登录必改密。注册回执加密、请求幂等，改密后不再返回旧初始密码。 |
| 完整股票绑定后账户才可用 | 统一 `accountReady` 检查网页、机器人、自选及交易；未绑定账户只可办理登录、改密、重置、绑定与退出。挂单成交也核验绑定，迁移取消旧未绑定账户挂单；新用户与删股后用户都看到必须完成的绑定引导。 |
| 全部机器人功能在群内完成 | 插件业务层 `_private` 及适配器敏感回复拦截删除。注册、密码重置、持仓、股票绑定、查询、预览、确认与取消均在原群回复；密码保持纯文本原样，不转成图片或改写字符。确认仍限发起人、应用及原会话。 |
| 恢复旧交易功能 | 见下表。复用旧图表与指标源码，接入当前 v2 API；交易站与管理站均提供亮暗主题。实际成交独立落账，月赛、排名、自选、损益与费用有完整数据链路。 |
| 管理员删股与 AzurPilot 停报、解绑 | `DeleteStock` 一次事务结清相关持仓、旧区间费用、实际回补损失补偿与挂单，解除绑定并写墓碑。原实例各端点返回 410 `STOCK_DELETED`；AzurPilot 持久保存删除状态及独立墓碑，退出上传监视，重启也不重试；交易账户重新绑定其他股票后恢复。 |

## 数据、会话与回滚

- 现有 v2 账户、密码哈希、官方身份、股票绑定、持仓、余额、订单与原始报价保留。启动时一次事务补入私有身份码、委托类型/有效期与旧成交聚合标记，并清除遗留网页注册密钥。失败不会留下部分迁移。
- 未绑定旧账户立即停止账户功能准入，待成交委托取消并释放冻结。已绑定账户继续使用原密码和 Cookie；改密、重置或停用仍撤销相应旧会话。删股不删除交易账户及密码，解绑后同一会话只能继续办理绑定等账户准备操作。
- 旧版只保存订单累计成交，无法还原每次部分成交时间/价格；保留明确标注的旧汇总，不编造逐笔。旧订单可核对的交易费可以补入统计，旧借券/融资持有费用和历史已实现盈亏无法完整反推。旧账户带 `legacyMetrics/metricsSince`，界面明确提示；存量空头以升级时卖空所得建立成本基线，后续新交易精确记录。下一赛季重置后恢复完整统计口径。
- 删除使用持久墓碑，原股票 ID、实例 UUID/公钥不复用。相关持仓按最后报价结清，零报价也允许系统结清；实际收不到的强平费用不计作已收收入。原始行情、旧订单与新逐笔保留用于核对，公开列表不再展示已删除股票。
- AzurPilot 保留 UUID、Ed25519 私钥与增量协议，增加受保护的删除登记、能力声明和告知参数；无实例私钥、交易 Cookie 或服务端凭据进入前端。删除登记应连同整个 `config/stock-exchange/` 备份。
- **旧镜像不能直接作为安全回滚方案。** 旧程序忽略/覆盖新字段，可能重新开放未绑定账户、忽略删股墓碑、丢失统计或复用成交编号。发布前停服备份专用 PostgreSQL、旧镜像/静态产物及 AzurPilot 股票保护目录；需回滚时停服务并配套恢复该版本备份，另行核对备份后的游戏交易。旧 SQLite 不受本次迁移影响，也未自动转换为 v2。

## 兼容性与发布顺序

以下为相对于本次改动前仓库工作区的契约审查及本地测试结论；后续生产部署已核实原站为初版 v2，实际切换范围及线上验收见部署记录。

| 组合 | 结论 |
| --- | --- |
| 新 Go 后端 + 旧交易站 | 公开摘要/规则/原图表接口仍可读，但旧网页注册已删除；未绑定账户不能继续交易。旧 UI 无新的准备流程和恢复功能，必须配套更新。 |
| 新 Go 后端 + 旧管理站 | 既有读取/规则/库存接口保留；旧余额写入缺 expectedCash、停用缺确认会被拒绝；无删股入口。必须配套更新。 |
| 新 Go 后端 + 旧 AzurPilot 同步端 | 原 register/status/report/manifest 签名及增量语义保留，现存未删股票可继续上报。旧端不会持久停止被删股票的重试；新服务端始终拒绝旧身份上传，因此完整删股要求必须更新 AzurPilot。 |
| 新交易站/管理站 + 旧 Go 后端 | 不兼容新开户、赛季/详情/自选/删除与管理接口，必须先提供新后端。 |
| 新插件 + 旧 Go 后端（或反向组合） | 注册请求/响应已替换，不兼容。插件和 Go 后端需同批更新；旧机器人注册密钥不再可消费。 |
| 新 AzurPilot 同步后端 + 旧 v2 Go | 原实例上报继续可用，能力未声明时不发送 reconcile；旧 Go 不支持删股，无法提供该功能。 |
| 新 AzurPilot 前端 + 旧 AzurPilot 后端 | 新 noticeVersion 不能被旧严格参数模型接受；需配套更新。新 AzurPilot 后端 + 旧前端的新股票注册会缺告知确认；既存股票同步保留。 |

建议顺序：备份 → 发布新 Go 后端 → 发布完整交易站/管理站产物与插件 → 同批更新 AzurPilot 后端及前端、重启 AzurPilot → 验证新开户、改密、绑定、交易及删股停报。更新期间可使用现有暂停市场设置控制游戏成交；交易所后端和配套站点已部署，AzurPilot 发布及插件加载不属于本次服务器操作。

| 更新范围 | 原因与生效步骤 |
| --- | --- |
| **必须更新：交易所 Go 后端** | 运行代码、身份准入、账本与契约变化；安装目录执行 `docker compose up -d --build exchange`。 |
| **必须更新：交易站和管理前端** | 构建并部署整个 `frontend/dist/`，最后切换 index.html。挂载路径不变通常无需额外重启 Go。 |
| **必须更新：AzurPilot 股票前端** | 告知确认、群内命令、删除状态与恢复入口；更新该仓完整前端产物。 |
| **必须更新：AzurPilot 同步后端** | 删除状态持久停止、签名校对与告知校验；更新 Python 后端并重启 AzurPilot。 |
